# EstateArg — интерактивная карта объектов: контекст для Claude Code

Этот документ — вводный контекст для работы над отдельной задачей внутри проекта EstateArg/ApartmentHuntersBA (Telegram-канал по недвижимости в Буэнос-Айресе, @EstateArg). Публикация объектов в канал ведётся в другом потоке работы — сюда это не относится, здесь только карта.

## Задача

Интерактивная карта объектов недвижимости (аренда + продажа) по Буэнос-Айресу. Разработка — локально на компьютере пользователя; перенос на сервер/хостинг — на финальном этапе, когда карта уже рабочая. На старте не привязываться к конкретному хостингу — делать как обычный статический веб-проект (HTML/CSS/JS, можно с любым современным фронтенд-стеком), который потом можно задеплоить куда угодно (VPS, Netlify, GitHub Pages и т.п.).

**Доступ к таблице:** гугл-таблица, владелец — пользователь (lukomorie1@gmail.com). Варианты получения данных для карты:
1. Опубликовать таблицу как CSV по ссылке (File → Share → Publish to web) и подтягивать на клиенте/при сборке — просто, но таблица станет публично читаемой по прямой ссылке.
2. Google Sheets API с OAuth/service account — приватно, но сложнее в настройке.
3. Периодический экспорт вручную/скриптом в JSON-файл, который коммитится в репозиторий карты — самый простой и предсказуемый вариант для старта, раз таблица меняется не ежеминутно.

**ВАЖНО — координат почти нет.** Поля `lat`/`lng` на 2026-11-05 пустые почти у всех объектов. Для точек на карте нужно либо:
- геокодировать `address` (+ `district` + ", Buenos Aires, Argentina") при сборке/рендере через геокодер (Nominatim/OpenStreetMap — бесплатно, с лимитом запросов; или Google Geocoding API — платный после лимита) с кэшированием результата, чтобы не геокодировать повторно одни и те же адреса;
- либо проставить координаты в таблице вручную один раз на объект.

У части объектов (A-0003, A-0004) нет точного адреса вообще (только название здания/район) — геокодировать можно будет только приблизительно, по названию здания и району, без гарантии точности.

## Границы районов (barrios) — новый источник

Датасет портала открытых данных Буэнос-Айреса:
**https://data.buenosaires.gob.ar/sq/dataset/barrios**

Со слов пользователя на этой странице доступны (я сам не смог открыть страницу — домен блокирует автоматический доступ из этого чата через robots.txt, поэтому точных прямых ссылок на файлы у меня нет — не выдумываю их):
- **SHP** — географические границы районов
- **GeoJSON** — координаты и геометрия районов (для веб-карты нужен скорее всего именно этот формат)
- **XLSX** — таблица с информацией о районах
- **CSV** — данные о районах
- отдельная **таблица соответствия районов коммунам** (barrio ↔ comuna)

**Первый шаг для Claude Code:** открыть страницу выше напрямую (с компьютера пользователя — там это ограничение, скорее всего, не действует), найти ресурс в формате GeoJSON и скачать его. Таблица соответствия barrio↔comuna — про запас, на случай если понадобится группировка по коммунам (административным округам); в таблице объектов сейчас есть только `district` (конкретный barrio), деления по комунам нет.

## Рекомендуемый технический подход

ВНИМАНИЕ: дальше — аналитическое предположение и рекомендация, а не единственно верный вариант.

- Карта: Leaflet.js (лёгкий, бесплатный, хорошо работает со произвольным GeoJSON) — слой с подсвеченными границами barrios из GeoJSON + слой маркеров объектов (из экспортированных данных таблицы).
- Попап на маркере: адрес, тип (аренда/продажа), цена (в том же формате, что в Telegram-постах — `USD 850$/мес`, см. ниже), 1-2 ключевых удобства, ссылка на пост в Telegram-канале (`tg_post_url`), если есть.
- Фильтры: тип объекта (аренда/продажа), район, диапазон цены, возможно — наличие бассейна/спортзала и т.п. (данные для этого уже есть в таблице: `pool`, `gym` и др.).
- Структура: один статический HTML-файл + JS/CSS — удобно разрабатывать локально (просто открыть в браузере) и легко перенести на любой хостинг в финале, без бэкенда вообще, если данные — просто JSON-файл в репозитории.

## Для единообразия с каналом (не обязательно, но желательно)

- Денежные суммы в USD — формат `USD 850$/мес` (знак $ сразу после числа, без пробела). Для ARS/expensas — без добавления `$` после суммы, просто `ARS 320 000`.
- Названия районов и важные термины — можно дублировать на риоплатском испанском в скобках, как в текстах объявлений (не обязательно для технических лейблов интерфейса).
